Introduction

Avant de commencer

Ce que vous allez mettre en place

Votre site va tourner sur un serveur privé virtuel (VPS) que vous louez au mois. Quand un visiteur tape mondomaine.fr, l’annuaire d’internet (le DNS) lui donne l’adresse de votre serveur. Sur celui-ci, Caddy gère le cadenas HTTPS et transmet les visites au site, qui enregistre vos contenus et les demandes reçues. Le code, lui, vit sur GitHub : chaque nouvelle version y est publiée, puis récupérée par le serveur.

01

Partie 1 · PréparerSur votre ordinateur5 min

Créer votre clé SSH

La clé SSH vous permettra de vous connecter au serveur sans mot de passe, de façon bien plus sûre.

Une clé SSH est une paire de fichiers. La clé privée reste sur votre ordinateur et ne doit jamais être partagée. La clé publique peut être donnée sans risque, par exemple à votre hébergeur : le serveur n’acceptera que l’ordinateur qui possède la clé privée correspondante.

  1. Ouvrez un terminal.
    • Windows 10 ou 11 : menu Démarrer, tapez Terminal (ou PowerShell) et ouvrez-le.
    • macOS : Applications›Utilitaires›Terminal.
    • Linux : ouvrez l’application Terminal.
  2. Créez la clé (la commande est la même partout) :
    Sur votre ordinateur
    ssh-keygen -t ed25519 -C "subnet"

    Appuyez sur Entrée pour accepter l’emplacement proposé. Choisissez ensuite une phrase de passe et confirmez-la : elle protège la clé si votre ordinateur est perdu ou volé. Rien ne s’affiche pendant la saisie, c’est normal.

  3. Affichez votre clé publique :
    Sur votre ordinateur · macOS et Linux
    cat ~/.ssh/id_ed25519.pub
    Sur votre ordinateur · Windows (PowerShell)
    Get-Content $env:USERPROFILE\.ssh\id_ed25519.pub
    Résultat attendu
    ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAIK3nZ8v…q9Xc subnet

    Copiez toute la ligne et gardez-la sous la main : vous la collerez chez l’hébergeur à l’étape 3.

Gardez la clé privée pour vous

Le fichier id_ed25519 (sans .pub) ne doit jamais être envoyé, copié dans un email ni publié. Si vous changez d’ordinateur, créez une nouvelle clé et ajoutez-la au serveur (étape 5).

Windows : « ssh-keygen » est introuvable ?

Le client SSH est intégré à Windows 10 et 11. S’il manque : Paramètres›Système›Fonctionnalités facultatives, puis ajoutez Client OpenSSH et rouvrez le terminal.

Réserver votre nom de domaine

Acheter l’adresse de votre site, par exemple mondomaine.fr, auprès d’un registrar.

Un registrar est la société auprès de laquelle vous louez votre nom de domaine, à l’année. Choisissez-en un qui inclut la gestion de la zone DNS : c’est le cas de ceux-ci.

RegistrarEn bref
OVHcloudFrançais, très répandu, interface en français.
GandiFrançais, interface claire.
InfomaniakSuisse, engagé sur l’écologie.
IONOSInterface en français ; vérifiez le prix du renouvellement.
  1. Cherchez le nom souhaité sur le site du registrar : court, facile à dicter, sans tiret si possible. Le .fr est réservé aux personnes et entreprises établies dans l’Union européenne, ce qui est le cas d’une entreprise française.
  2. Refusez les options inutiles lors de la commande : hébergement web, créateur de site, certificat SSL payant. Ce guide installe un certificat HTTPS gratuit.
  3. Option utile : une adresse email à votre nom, comme contact@mondomaine.fr. Elle servira d’adresse de contact et pour envoyer les notifications du site (étape 9). Certains registrars en offrent une avec le domaine.
  4. Activez le renouvellement automatique : un domaine expiré rend le site et les emails injoignables.

Résultat

Dans votre espace client, vous voyez votre domaine et sa zone DNS. Vous y reviendrez à l’étape 4.

03

Partie 1 · PréparerDans le navigateur10 min

Louer votre serveur (VPS)

Louer la machine sur laquelle le site tournera, jour et nuit.

Un VPS (serveur privé virtuel) est un serveur loué au mois chez un hébergeur. Vous en êtes l’administrateur : vous y installerez le site en quelques commandes. Hébergeurs reconnus : OVHcloud et Scaleway (France), Hetzner (Allemagne, Finlande), IONOS, Infomaniak (Suisse). Les offres d’entrée de gamme, autour de 5 à 10 € par mois, suffisent largement.

ÉlémentÀ choisir
SystèmeUbuntu Server 26.04 LTS (ou 24.04 LTS). « LTS » signifie maintenu pendant au moins cinq ans.
Processeur1 à 2 vCPU
Mémoire2 Go minimum, 4 Go confortable
Stockage20 Go SSD ou plus
LocalisationFrance ou Union européenne (RGPD et rapidité pour vos visiteurs)
RéseauAdresse IPv4 publique incluse (c’est presque toujours le cas)
  1. Commandez le VPS en choisissant l’image Ubuntu Server LTS.
  2. Ajoutez votre clé SSH quand l’interface le propose (champ « Clé SSH » ou « SSH key ») : collez la ligne copiée à l’étape 1.
  3. Activez les sauvegardes de l’hébergeur si l’option existe (« backups » ou « snapshots ») : pour quelques euros par mois, vous pourrez restaurer tout le serveur.
  4. Une fois le serveur livré (en quelques minutes), notez :
    • son adresse IPv4, par exemple 203.0.113.10 ;
    • son adresse IPv6 si elle est indiquée, par exemple 2001:db8::10 ;
    • le nom d’utilisateur de connexion, indiqué par l’hébergeur : souvent root, ou ubuntu chez OVHcloud.

Pas de champ pour la clé SSH ?

L’hébergeur vous envoie alors un mot de passe par email. Vous ajouterez votre clé lors de la première connexion (encadré de l’étape 5).

04

Partie 1 · PréparerDans le navigateur10 min + attente

Relier le domaine au serveur (DNS)

Indiquer à internet que mondomaine.fr correspond à l’adresse de votre serveur. On le fait dès maintenant : la mise à jour peut prendre jusqu’à quelques heures.

  1. Ouvrez la zone DNS dans l’espace client du registrar, par exemple : Noms de domaine›mondomaine.fr›Zone DNS.
  2. Supprimez les entrées A, AAAA et CNAME existantes pour le domaine principal (sous-domaine vide ou @) et pour www : elles pointent vers une page d’attente du registrar. Ne touchez pas aux entrées MX et TXT, qui servent aux emails.
  3. Ajoutez ces entrées, en laissant le TTL proposé :
    TypeSous-domaineCible
    Avide (ou @)203.0.113.10
    Awww203.0.113.10
    AAAAvide (ou @)2001:db8::10 · seulement si votre VPS a une IPv6
    AAAAwww2001:db8::10 · idem
  4. Vérifiez, au bout de quelques minutes :
    Sur votre ordinateur
    nslookup mondomaine.fr
    Résultat attendu
    Non-authoritative answer:
Name:    mondomaine.fr
Address: 203.0.113.10

    La réponse doit contenir l’adresse de votre serveur. Vous pouvez aussi vérifier sur dnschecker.org.

IPv6 : seulement si elle fonctionne

Une entrée AAAA vers une adresse IPv6 non configurée sur le serveur bloque une partie des visiteurs et peut empêcher l’obtention du certificat HTTPS. Dans le doute, n’ajoutez que les entrées A : l’IPv4 suffit.

La propagation

Selon le registrar, la nouvelle adresse est visible en quelques minutes ou quelques heures. Continuez les étapes suivantes en attendant : le DNS doit simplement être en place à l’étape 10.

Partie 2 · InstallerOrdinateur puis serveur10 min

Vous connecter au serveur

Ouvrir une session sur le serveur et installer ses mises à jour.

  1. Connectez-vous avec l’utilisateur fourni par l’hébergeur (root, ou ubuntu chez OVHcloud) :
    Sur votre ordinateur
    ssh root@203.0.113.10

    À la première connexion, le terminal demande si vous faites confiance au serveur (Are you sure you want to continue connecting?) : tapez yes puis Entrée. Saisissez ensuite la phrase de passe de votre clé.

    Résultat attendu
    Welcome to Ubuntu 26.04 LTS (GNU/Linux …)
…
root@vps-subnet:~#

    Vous êtes connecté : les commandes que vous tapez s’exécutent désormais sur le serveur. Pour revenir au terminal de votre ordinateur, tapez exit.

  2. Installez les mises à jour et quelques outils, puis réglez le fuseau horaire :
    Sur le serveur
    sudo apt update && sudo apt full-upgrade -y
sudo apt install -y git ufw unattended-upgrades
sudo timedatectl set-timezone Europe/Paris

    Si un écran demande quels services redémarrer, validez simplement avec Entrée.

  3. Redémarrez pour appliquer les mises à jour :
    Sur le serveur
    sudo reboot

    La connexion se ferme. Patientez une minute, puis reconnectez-vous avec la même commande qu’au point 1.

Vous vous êtes connecté avec un mot de passe ?

Si l’hébergeur vous a fourni un mot de passe plutôt que d’enregistrer votre clé, ajoutez-la maintenant, depuis votre ordinateur (remplacez ubuntu par votre utilisateur) :

Sur votre ordinateur · macOS et Linux
ssh-copy-id ubuntu@203.0.113.10
Sur votre ordinateur · Windows (PowerShell)
$key = Get-Content $env:USERPROFILE\.ssh\id_ed25519.pub
ssh ubuntu@203.0.113.10 "mkdir -p ~/.ssh; echo '$key' >> ~/.ssh/authorized_keys"

La connexion suivante ne demandera plus le mot de passe du serveur.

06

Partie 2 · InstallerSur le serveur15 min

Sécuriser le serveur

Créer votre propre utilisateur, interdire les connexions par mot de passe et n’ouvrir que les ports nécessaires.

6.1Créer votre utilisateur

Plutôt que de travailler avec le compte root, créez un utilisateur personnel, ici subnet, autorisé à agir en administrateur avec sudo. Les quatre dernières commandes lui copient votre clé SSH.

Sur le serveur
sudo adduser subnet
sudo usermod -aG sudo subnet
sudo mkdir -p /home/subnet/.ssh
sudo cp ~/.ssh/authorized_keys /home/subnet/.ssh/
sudo chown -R subnet:subnet /home/subnet/.ssh
sudo chmod 700 /home/subnet/.ssh && sudo chmod 600 /home/subnet/.ssh/authorized_keys

adduser demande un mot de passe : choisissez-le solide et rangez-le dans votre gestionnaire de mots de passe, sudo vous le demandera. Les questions suivantes (nom complet, téléphone…) sont facultatives : Entrée à chaque fois.

6.2Tester la nouvelle connexion

Sans fermer la session en cours, ouvrez un second terminal sur votre ordinateur :

Sur votre ordinateur · nouveau terminal
ssh subnet@203.0.113.10
Sur le serveur · connecté en tant que subnet
sudo whoami
Résultat attendu (après le mot de passe de subnet)
root

6.3Interdire les mots de passe et le compte root

Sur le serveur
sudo tee /etc/ssh/sshd_config.d/00-subnet.conf > /dev/null <<'EOF'
PermitRootLogin no
PasswordAuthentication no
KbdInteractiveAuthentication no
EOF
sudo sshd -t && sudo systemctl restart ssh
sudo sshd -T | grep -E 'permitrootlogin|passwordauthentication'
Résultat attendu
permitrootlogin no
passwordauthentication no

Vérifiez dans un nouveau terminal que ssh subnet@203.0.113.10 fonctionne toujours. Désormais, connectez-vous toujours ainsi : la connexion avec root et par mot de passe est refusée.

Pourquoi « 00- » dans le nom du fichier ?

La plupart des VPS contiennent déjà un fichier 50-cloud-init.conf qui autorise les mots de passe. SSH retient la première valeur lue : le préfixe 00- garantit que vos réglages passent avant. Avec un autre nom, ils pourraient être ignorés sans aucun message.

Ne vous enfermez pas dehors

Gardez une session ouverte tant qu’une nouvelle connexion n’a pas réussi. En cas de blocage, la console de secours de l’hébergeur (KVM, VNC ou console web) permet toujours de reprendre la main.

6.4Activer le pare-feu

Sur le serveur
sudo ufw allow OpenSSH
sudo ufw allow 80/tcp
sudo ufw allow 443
sudo ufw enable
sudo ufw status

À la question Proceed with operation (y|n)?, répondez y.

Résultat attendu
Status: active

To                         Action      From
--                         ------      ----
OpenSSH                    ALLOW       Anywhere
80/tcp                     ALLOW       Anywhere
443                        ALLOW       Anywhere
…

Seuls SSH (port 22), HTTP (80) et HTTPS (443) sont ouverts. Le site lui-même (port 3000) n’est jamais exposé : Caddy reste le seul point d’entrée.

6.5Correctifs de sécurité automatiques

Sur le serveur
sudo dpkg-reconfigure -plow unattended-upgrades

Répondez Oui (Yes) : les correctifs de sécurité du système s’installeront désormais chaque nuit.

Partie 2 · InstallerSur le serveur5 min

Installer Docker

Installer Docker, qui fait tourner le site et Caddy dans des conteneurs isolés, faciles à mettre à jour.

Docker emballe une application avec tout ce dont elle a besoin (ici Node.js) : rien d’autre à installer sur le serveur. Connecté en tant que subnet, copiez ce bloc en entier : ce sont les commandes de la documentation officielle de Docker.

Sur le serveur
sudo apt install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc
sudo tee /etc/apt/sources.list.d/docker.sources > /dev/null <<EOF
Types: deb
URIs: https://download.docker.com/linux/ubuntu
Suites: $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}")
Components: stable
Architectures: $(dpkg --print-architecture)
Signed-By: /etc/apt/keyrings/docker.asc
EOF
sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

Vous avez choisi Debian ? Remplacez ubuntu par debian dans les deux adresses download.docker.com.

Autorisez ensuite votre utilisateur à se servir de Docker, puis fermez la session :

Sur le serveur
sudo usermod -aG docker subnet
exit

Reconnectez-vous (ssh subnet@203.0.113.10) pour que ce droit soit pris en compte, puis vérifiez :

Sur le serveur
docker run --rm hello-world
docker compose version
Résultat attendu
Hello from Docker!
This message shows that your installation appears to be working correctly.
…
Docker Compose version v5.6.0

Le numéro de version peut être différent : c’est sans importance.

Le groupe docker

Être membre du groupe docker revient à avoir les droits d’administrateur du serveur : ne l’accordez qu’à votre utilisateur.

Partie 2 · InstallerGitHub puis serveur15 min

Publier le code et le récupérer sur le serveur

Valider la version du site sur GitHub (branche main), puis la copier sur le serveur.

8.1Fusionner la version de travail dans main

Le code du site est sur GitHub, dans le dépôt Raphioooo/Subnet. Les derniers développements sont sur la branche claude/subnet-site-descriptif-604gbe. La branche main est celle que le serveur met en ligne : on y fusionne le travail par une pull request.

  1. Sur github.com, ouvrez le dépôt, puis Pull requests›New pull request.
  2. Choisissez base : main et compare : claude/subnet-site-descriptif-604gbe, puis cliquez deux fois sur Create pull request.
  3. Patientez une à deux minutes : GitHub lance les tests automatiques. Quand la coche verte apparaît, cliquez sur Merge pull request, puis Confirm merge.

C’est ainsi pour chaque nouvelle version

Une pull request fusionnée dans main, c’est une nouvelle version prête à être mise en ligne. À l’étape 12, cette mise en ligne deviendra automatique.

8.2Donner au serveur un accès en lecture au dépôt

Le dépôt est privé : le serveur a besoin de sa propre clé, autorisée uniquement à lire ce dépôt (une « deploy key »).

Sur le serveur
ssh-keygen -t ed25519 -N "" -C "serveur-subnet" -f ~/.ssh/github
cat ~/.ssh/github.pub

Copiez la ligne affichée (ssh-ed25519 …). Sur GitHub, dans le dépôt : Settings›Deploy keys›Add deploy key. Titre : Serveur VPS ; Key : collez la ligne ; laissez Allow write access décoché ; validez avec Add key. Puis, sur le serveur :

Sur le serveur
cat >> ~/.ssh/config <<'EOF'
Host github.com
  IdentityFile ~/.ssh/github
  IdentitiesOnly yes
EOF
chmod 600 ~/.ssh/config
ssh -T git@github.com

La première fois, vérifiez que l’empreinte affichée est bien celle de GitHub, SHA256:+DiY3wvvV6TuJJhbpZisF/zLDA0zPMSvHdkr4UvCOqU, puis tapez yes.

Résultat attendu
Hi Raphioooo/Subnet! You've successfully authenticated, but GitHub does not provide shell access.

Partie 2 · InstallerSur le serveur10 min

Configurer le site

Renseigner votre domaine et, si vous le souhaitez, l’envoi d’un email à chaque demande reçue.

Sur le serveur
cd ~/site
cp .env.example .env
chmod 600 .env
nano .env

Le fichier s’ouvre dans l’éditeur nano. Déplacez-vous avec les flèches du clavier et complétez au minimum ces deux lignes, sans espace autour du signe = :

Fichier .env
DOMAIN=mondomaine.fr
BASE_URL=https://mondomaine.fr

Enregistrez avec Ctrl O puis Entrée, et quittez avec Ctrl X.

RéglageQue mettre ?
ADMIN_PASSWORDLaissez vide (recommandé). Un mot de passe temporaire s’affichera au premier démarrage, et vous choisirez le vôtre dans l’administration : il sera enregistré chiffré, et non en clair dans ce fichier.
SESSION_SECRETLaissez vide : une clé secrète est générée automatiquement.
SMTP_…, MAIL_…Facultatif : pour recevoir un email à chaque demande (ci-dessous).
PORT, NODE_ENV, DATA_DIR, TRUST_PROXYNe pas modifier : les valeurs conviennent à Docker et Caddy.

Recevoir un email à chaque demande (facultatif)

Sans ce réglage, les demandes restent consultables dans l’administration (rubrique Demandes). Pour être prévenu par email, indiquez une boîte email existante qui servira d’expéditeur. Exemple avec une adresse OVHcloud :

Fichier .env · exemple
SMTP_HOST=ssl0.ovh.net
SMTP_PORT=587
SMTP_SECURE=false
SMTP_USER=contact@mondomaine.fr
SMTP_PASS=mot-de-passe-de-la-boite
MAIL_TO=vous@exemple.fr
FournisseurSMTP_HOSTSMTP_USER et SMTP_PASS
Email OVHcloudssl0.ovh.netl’adresse et le mot de passe de la boîte
Gmailsmtp.gmail.coml’adresse Gmail et un mot de passe d’application (validation en deux étapes requise)
Brevosmtp-relay.brevo.coml’identifiant et la clé SMTP fournis par Brevo

Gardez le port 587 avec SMTP_SECURE=false (chiffrement STARTTLS) : certains hébergeurs, dont Hetzner, bloquent les ports 25 et 465. MAIL_TO est l’adresse qui reçoit les notifications ; sans elle, c’est l’email de contact saisi dans l’administration.

Modifier le fichier .env plus tard

Après chaque modification, appliquez-la avec docker compose up -d, depuis le dossier ~/site.

Démarrer le site en HTTPS

Lancer le site et Caddy : le certificat HTTPS est obtenu tout seul.

Avant de lancer

Le DNS de l’étape 4 doit déjà pointer vers le serveur : nslookup mondomaine.fr doit renvoyer son adresse. Sinon, Caddy ne peut pas obtenir le certificat.

Sur le serveur
cd ~/site
docker compose up -d --build

La première construction prend une à trois minutes. Vérifiez ensuite que tout tourne :

docker compose ps
Résultat attendu

Les deux services doivent être Up, et le site (healthy) au bout de quelques secondes.

Vérifier le certificat HTTPS

… "msg":"certificate obtained successfully","identifier":"www.mondomaine.fr", …

Ouvrez alors https://mondomaine.fr dans votre navigateur : le site s’affiche avec le cadenas. Les adresses www.mondomaine.fr et http://mondomaine.fr redirigent automatiquement vers https://mondomaine.fr.

Votre site est en ligne

Le certificat sera renouvelé automatiquement par Caddy, sans aucune intervention. Si le serveur redémarre, le site redémarre aussi tout seul.

Pas de certificat ?

Vérifiez le DNS (étape 4) et le pare-feu (étape 6.4), puis relancez Caddy avec docker compose restart caddy. Voir aussi le dépannage, en fin de guide.

Mettre à jour le site à chaque push

Publier une nouvelle version du code en une commande, puis automatiquement à chaque fusion dans main.

Les textes, photos, horaires et demandes se gèrent dans l’administration : ces changements sont en ligne immédiatement, sans mise à jour. Une mise à jour n’est utile que lorsque le code du site change : nouvelle fonctionnalité, correction, nouveau design.

12.1Mise à jour manuelle

Sur le serveur
~/site/scripts/deploy.sh

Le script récupère la dernière version de main, met à jour Node.js et Caddy, reconstruit le site puis le redémarre, avec quelques secondes d’interruption. Vos contenus et vos demandes ne sont pas touchés.

12.2Mise à jour automatique à chaque push sur main

Le dépôt contient déjà le workflow GitHub Actions (.github/workflows/deploy.yml). Il reste à lui donner accès au serveur avec une clé limitée : elle ne peut lancer que le script de mise à jour, rien d’autre.

  1. Sur le serveur, créez la clé et réservez-la au script de mise à jour :
    Sur le serveur
    ssh-keygen -t ed25519 -N "" -C "github-actions" -f ~/.ssh/github_actions
KEY=$(cat ~/.ssh/github_actions.pub)
echo "command=\"$HOME/site/scripts/deploy.sh\",restrict $KEY" >> ~/.ssh/authorized_keys
cat ~/.ssh/github_actions
ssh-keyscan -t ed25519 mondomaine.fr
  2. Sur GitHub, dans le dépôt : Settings›Secrets and variables›Actions›New repository secret. Créez ces quatre secrets :
    NomValeur
    DEPLOY_HOSTmondomaine.fr
    DEPLOY_USERsubnet
    DEPLOY_SSH_KEYtout le bloc affiché par cat, de -----BEGIN OPENSSH PRIVATE KEY----- à -----END OPENSSH PRIVATE KEY----- inclus
    DEPLOY_KNOWN_HOSTSla ligne affichée par ssh-keyscan (mondomaine.fr ssh-ed25519 AAAA…)
  3. Supprimez la clé privée du serveur : GitHub en garde la seule copie, chiffrée.
    Sur le serveur
    rm ~/.ssh/github_actions ~/.ssh/github_actions.pub
  4. Testez : sur GitHub, Actions›Tests et mise en ligne›Run workflow (branche main). Les étapes Tests et Mise en ligne doivent passer au vert ; le journal de la seconde affiche l’état des conteneurs.

12.3Votre cycle de travail

Pour chaque évolution, les modifications sont faites sur une branche, par vous ou par Claude. Une pull request est ouverte et les tests s’exécutent. Quand vous la fusionnez dans main, le site est mis à jour automatiquement, en deux à trois minutes.

Revenir en arrière

Une nouvelle version pose problème ? Sur GitHub, ouvrez la pull request fusionnée et cliquez sur Revert, puis fusionnez la pull request ainsi créée : la version précédente est remise en ligne automatiquement.

Sauvegarder les données

Mettre en place une sauvegarde quotidienne automatique, en garder une copie hors du serveur et savoir restaurer.

Le code est à l’abri sur GitHub. Ce qu’il faut sauvegarder, ce sont les données : textes et réglages, demandes reçues, images envoyées et mot de passe de l’administration.

13.1Sauvegarde manuelle

Sur le serveur
~/site/scripts/backup.sh
Résultat attendu
Sauvegarde créée : backups/subnet-2026-10-16-033000.tar.gz (2.1M)

Les archives sont rangées dans ~/site/backups ; les 14 plus récentes sont conservées.

13.2Sauvegarde automatique chaque nuit

Sur le serveur
crontab -e

La première fois, choisissez l’éditeur nano (tapez 1). Ajoutez cette ligne à la fin du fichier, puis enregistrez (Ctrl O, Entrée, Ctrl X) :

Ligne à ajouter
30 3 * * * $HOME/site/scripts/backup.sh >> $HOME/sauvegardes.log 2>&1

Une sauvegarde sera créée chaque nuit à 3 h 30. Le fichier ~/sauvegardes.log garde la trace de chaque exécution.

13.3Garder une copie hors du serveur

Si le serveur disparaît, ses sauvegardes aussi. Rapatriez-les régulièrement sur votre ordinateur, au moins une fois par mois :

Sur votre ordinateur
scp -r subnet@mondomaine.fr:site/backups ./sauvegardes-subnet

Conservez aussi une copie du fichier .env dans votre gestionnaire de mots de passe. Les sauvegardes proposées par l’hébergeur (étape 3) complètent utilement ce dispositif.

13.4Restaurer une sauvegarde

Sur le serveur
ls ~/site/backups
~/site/scripts/restore.sh ~/site/backups/subnet-2026-10-16-033000.tar.gz

Le script sauvegarde d’abord l’état actuel, puis remplace les données par celles de l’archive et redémarre le site. Faites un essai une fois : une sauvegarde n’est fiable que si l’on sait la restaurer.

Depuis l’administration

Compte et sauvegarde›Télécharger une sauvegarde exporte les textes et réglages (sans les images) : pratique avant une grosse modification de contenu.

Entretenir et surveiller

Garder le serveur à jour, être prévenu si le site ne répond plus et bien apparaître sur Google.

Une fois par mois

Sur le serveur
sudo apt update && sudo apt full-upgrade -y
~/site/scripts/deploy.sh
df -h /
tail -n 3 ~/sauvegardes.log

Ces commandes mettent à jour le système, puis Node.js, Caddy et le site. Elles affichent ensuite l’espace disque disponible et le résultat des dernières sauvegardes. Si le fichier /var/run/reboot-required existe, redémarrez avec sudo reboot : le site repart tout seul.

Être prévenu en cas de panne

Créez une surveillance gratuite sur UptimeRobot ou Better Stack : elle vérifie https://mondomaine.fr toutes les cinq minutes et vous envoie un email si le site ne répond plus.

Être bien référencé

Ajoutez votre domaine dans Google Search Console (vérification par un enregistrement TXT dans la zone DNS, comme à l’étape 4), puis déclarez le plan du site : https://mondomaine.fr/sitemap.xml. Le site génère ce fichier automatiquement.

À ne pas oublier

  • Le renouvellement du nom de domaine : automatique si vous l’avez activé, mais vérifiez la carte bancaire enregistrée.
  • Le paiement du VPS.
  • La copie de vos sauvegardes hors du serveur.

Le certificat HTTPS, lui, se renouvelle tout seul.

En cas de besoin

Dépannage

« Permission denied (publickey) » à la connexion SSH

Mauvais nom d’utilisateur, ou clé non reconnue par le serveur.

Vérifiez l’utilisateur : subnet après l’étape 6, sinon celui de l’hébergeur (root ou ubuntu). Utilisez-vous bien l’ordinateur qui possède la clé ? En dernier recours, la console de secours de l’hébergeur permet de vous reconnecter et de corriger ~/.ssh/authorized_keys.

Le domaine n’affiche pas votre site

DNS pas encore à jour, ou anciennes entrées toujours présentes.

Lancez nslookup mondomaine.fr : si l’adresse n’est pas celle du serveur, revoyez la zone DNS (étape 4), supprimez les anciennes entrées A, AAAA et CNAME, puis patientez.

Erreur de certificat, ou HTTPS qui ne répond pas

Caddy n’a pas pu obtenir le certificat.

Consultez docker compose logs caddy. Causes habituelles : DNS pas encore à jour, entrée AAAA incorrecte, ports 80 ou 443 fermés (sudo ufw status, et pare-feu éventuel dans l’interface de l’hébergeur), ou trop de tentatives (attendez une heure). Une fois corrigé : docker compose restart caddy.

« 502 Bad Gateway » ou page blanche

Le site ne tourne pas, ou redémarre (quelques secondes pendant une mise à jour).

Lancez docker compose ps puis docker compose logs --tail 50 site depuis ~/site. Pour relancer : docker compose up -d.

Mot de passe de l’administration oublié

Depuis ~/site, lancez docker compose exec site npm run set-password et choisissez un nouveau mot de passe : il s’applique immédiatement. Si vous aviez rempli ADMIN_PASSWORD dans .env, modifiez cette ligne puis lancez docker compose up -d.

Aucun email de notification

Réglages SMTP incorrects, port bloqué ou message classé en spam.

Lancez docker compose logs site | grep -i email pour voir l’erreur. Vérifiez les lignes SMTP_… de .env (port 587), puis docker compose up -d. Les demandes restent de toute façon visibles dans l’administration.

La mise en ligne automatique échoue (croix rouge sur GitHub)

Ouvrez le détail dans l’onglet Actions. Tests en échec : le code contient une erreur, rien n’a été mis en ligne. Permission denied : vérifiez DEPLOY_USER et DEPLOY_SSH_KEY. Host key verification failed : vérifiez DEPLOY_KNOWN_HOSTS. Erreur pendant git pull : vérifiez la deploy key (étape 8.2).

Une modification du code n’apparaît pas

La pull request a-t-elle été fusionnée dans main ? Le workflow est-il vert ? Vous pouvez toujours lancer la mise à jour à la main : ~/site/scripts/deploy.sh. La commande git -C ~/site log -1 affiche la version présente sur le serveur.

Disque plein

Lancez df -h / et docker system df. Faites de la place avec docker system prune -f (images inutilisées ; vos données ne sont pas concernées) et supprimez d’anciennes archives dans ~/site/backups.

Petit glossaire

TermeDéfinition
BrancheUne version parallèle du code. main est la version mise en ligne ; les évolutions se préparent sur d’autres branches.
CaddyLe « portier » du serveur : il reçoit les visites, gère le cadenas HTTPS et les transmet au site.
Clé SSHUne paire de fichiers qui remplace le mot de passe pour se connecter au serveur, de façon bien plus sûre.
ConteneurUne application emballée avec tout ce dont elle a besoin, isolée du reste du serveur. Docker les fait tourner.
DNSL’annuaire d’internet, qui traduit un nom de domaine en adresse IP.
GitHub ActionsLes automatismes de GitHub : ici, les tests et la mise en ligne à chaque fusion dans main.
HTTPSLa version chiffrée du web, signalée par le cadenas. Le certificat qui la permet est fourni gratuitement par Let’s Encrypt.
Pull requestUne demande de fusion d’une branche dans une autre, avec la liste des changements et le résultat des tests.
PushL’envoi de nouvelles modifications du code vers GitHub.
RegistrarLa société auprès de laquelle vous louez votre nom de domaine.
sudoLe préfixe qui exécute une commande avec les droits d’administrateur.
TerminalLa fenêtre où l’on tape des commandes, sur votre ordinateur comme sur le serveur.

VolumeL’espace de stockage d’un conteneur Docker, conservé lors des mises à jour.
